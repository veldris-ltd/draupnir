# DRAUPNIR

The CIM-56 model factory control plane.

> DRAUPNIR is the ring that, in the Norse sources, drips eight further rings of
> equal weight every ninth night. The name is taken for a system whose function
> is to turn one shared substrate into fifty six derived models.

Architecture: `docs/build/draupnir-sad.md` (VLD-SAD-DRAUPNIR-001).
Console and design system: `docs/build/draupnir-ux.md` (VLD-UX-DRAUPNIR-001).

---

## Start

```bash
make dev
```

One command from a clean machine to a running stack with seeded data. On
Windows, `.\make.ps1 dev`. See [docs/CONTRIBUTING.md](docs/CONTRIBUTING.md).

## Status

Prompt 0 of SAD section 13 is complete: the repository, the toolchain and the
delivery pipeline. There is no feature code yet, by design. What exists is the
set of rules the feature code will be built inside:

- Every stage of the pipeline in SAD 11H exists and runs, and none is
  skippable on main.
- The inward-only dependency rule of SAD 11B is enforced by an import linter
  from the first module, rather than asserted and checked at review.
- The three database-enforced constraints of SAD 11C are in the first
  migration and are attacked by integration tests.
- The generated CLI and TypeScript client are regenerated by the build, which
  fails on drift.
- A deterministic seed produces 2 sites, 6 sources, 12 runs across every run
  state, 3 releases and 400 hash-chained ledger entries.
- Playwright, axe and Storybook are wired and running against nothing yet.
